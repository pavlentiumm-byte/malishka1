# Развитие ВКадре по ТЗ от 27 октября 2026

## Границы

Статический HTML/CSS/JS, GitHub Pages, относительные пути. Только локальная интерактивная демонстрация. Не подключать сервер, платные API и не выполнять push/deploy без разрешения. Полное ТЗ: TECHNICAL-SPEC.md. Последнее ТЗ возвращает функцию предложения съёмки, отменяя предыдущее решение об удалении.

## Аудит исходного состояния

- `index.html`: последовательное подключение скриптов, хеш-маршрутизация; пути относительные.
- `app.js`: каталог с фильтрами, профиль и кадрирование, личные чаты, обычные сообщения/изображения/голосовые, избранное, портфолио, настройки, перевод. Каталог заполнен явно демонстрационными специалистами.
- `calendar.js`: личные события в localStorage, месяц и день; старые карточки связаны с событиями через agreement-ID. Свободные даты пока отдельный список без видимости.
- `collaboration.js`: вспомогательные формы/сохранение, доступность, старые сообщения-карточки.
- `planning.js`: объявления с упрощёнными фильтрами и откликами, старые договорённости, мудборды и задачи, напоминания только в открытом сайте.
- `interface.js`/`interface.css`: единая система элементов, навигация, улучшение загрузки файлов с сохранением исходного input, концепция Pro.
- `styles.css`: исходные стили, адаптивность, темы и стили компонентов.
- `auth.js`: только интерфейс неподключённых OAuth-провайдеров. Авторизации нет.
- Хранение: localStorage — профиль, настройки, сообщения, отклики и календарь. IndexedDB `vkadre-portfolio`, store `data` — проекты портфолио и вложения личных чатов.
- Портфолио: проекты с названием и фото; поля команды, дат, прав использования отсутствуют. Старые фотографии мигрируют в проекты.
- Безопасность: экранирование текста, проверка ссылок, локальные черновики жалоб на профили; блокировок и серверной модерации нет.
- Проверки: Swift + JavaScriptCore для логики и WebKit с отдельным непостоянным хранилищем для браузерных сценариев. Предыдущий интерфейс проверялся на 320/390/768/1280 px. Новые этапы требуют отдельных проверок.

## Повторное использование

`showModal`/`closeModal`, focus trap, `esc`, `tr`, `toast`, `pageIntro`, `interfaceIcon`, локальный профиль, справочник people, текущие чаты и механизм вложений. Новый доменный слой не должен перезаписывать старые ключи.

## Этапы

1. **Готово и проверено:** предложения, черновики, карточка договорённости, действия получателя с явной меткой локальной демонстрации, история, повторное согласование. Новый единый репозиторий проектов; ссылки в чате и производные события календаря.
2. **Реализовано; логика проверена, браузерная проверка ожидает:** расширенные объявления, профессии/число мест, жанры, сроки заявок, изображения/ссылки, редактирование/удаление, статус «Принят».
3. **Реализовано; логика проверена, браузерная проверка ожидает:** доступность (свободен/занят/предварительно), настройки видимости, подсказка в приглашении; подтверждённые проекты уже должны попадать в календарь без дублей.
4. **Реализовано; логика проверена, браузерная проверка ожидает:** групповые чаты, отдельные/прикрепляемые мудборды с сортировкой и комментариями, сохранённые команды.
5. **Implemented; browser QA pending:** расширение портфолио без потери старых записей, локальные отзывы после завершения, безопасный интерфейс заявки на верификацию.
6. **Implemented; browser QA pending:** демонстрационные студии/локации, измеримые локальные показатели, расширенные жалобы и блокировки.
7. **Ожидает:** общие регрессии, адаптивность/темы/языки, восстановление после загрузки и подпапка `/wkadre/`.

После каждого этапа обновлять этот файл: фактическая реализация, результаты проверок, ограничения и следующий шаг. Не объявлять весь проект законченным по результатам одного этапа.


## Результат этапа 1

Реализованы новая форма предложения, частичные черновики, проверка перед отправкой, карточка в личном чате, отдельный режим действий получателя (принять/отклонить/обсудить), причины отмены, история значений до/после, повторное согласование ключевых условий, завершение и раздел «Мои съёмки». Карточки и календарь строятся из одного источника; подтверждённые/завершённые записи появляются автоматически, отменённые/ожидающие согласования исключаются. Изменение только комментария не сбрасывает согласованные условия.

Файлы: `shoots-store.js` — версия схемы, нормализация, валидация, переходы и атомарное сохранение; `shoots.js` — формы, карточки и проекции; `shoots.css` — стили. Точки интеграции: `app.js`, `calendar.js`, `interface.js`, `index.html`. Патч-ноты: `changelog.js`. Предыдущие ключи и вложения не мигрируются и не удаляются.

Новый ключ `kadr-html-projects-v1`: schemaVersion, revision, records. У каждой записи своя revision для защиты от устаревших форм в нескольких вкладках. Повреждённая/неизвестная схема блокирует запись вместо молчаливого обнуления. Ошибка квоты не меняет исходные данные. У будущего API отдельная граница — ShootRepository.

Исправления: отправка обычного сообщения больше не ждёт бесконечно requestAnimationFrame в неактивной вкладке; для списка контактов снимок проектов читается один раз вместо повторного разбора на каждом сравнении.

### Как проверить

1. Открыть профиль специалиста → «Предложить съёмку».
2. Сохранить неполный черновик; найти его в Профиль → Мои съёмки.
3. Заполнить обязательные поля → Проверить предложение → Добавить предложение в чат.
4. Открыть карточку → Проверить действия получателя · демо → Принять · локально.
5. Перейти в календарь, затем изменить дату/время через карточку. До повторного принятия события нет в календаре.
6. Попробовать отказ с причиной, обсуждение, завершение и историю изменений.

Блокировка/разблокировка требует подтверждения.
